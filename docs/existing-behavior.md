# Existing behavior map

This is a **navigation aid for the incremental Svelte 5 migration** (#618), mapping behavior to evidence from the existing implementation.

The actual implementation and the tests/preexisting documentation are two kinds of evidence which can support a claim that certain behavior is intended in their own ways.

| Area | Implementation | Tests and preexisting documentation |
| --- | --- | --- |
| Board and selection | [Sudoku.tsx](../src/Elems/MainElems/Sudoku.tsx), [Cell.tsx](../src/Elems/MainElems/Cell.tsx) | [Sudoku.test.tsx](../src/Elems/MainElems/Sudoku.test.tsx) checks the labeled grid, focus and selection, and multiple-cell edits. The [keyboard notes](../src/Elems/MainElems/Sudoku.md) contain design ideas as well as descriptions of controls. |
| Candidate editing and fresh entry | [Cell.tsx](../src/Elems/MainElems/Cell.tsx): all nine candidates means an unconstrained cell; zero means an error. `toggleCandidate()` starts from an empty set while `pretend` is true. `updateSelectionStatus()` recalculates `pretend` from the candidate count when the selection is active. | [Sudoku.test.tsx](../src/Elems/MainElems/Sudoku.test.tsx) exercises single-digit entry, candidate toggling, resetting, clearing, and multiple-cell editing. |
| Keyboard controls | [Sudoku.tsx](../src/Elems/MainElems/Sudoku.tsx): arrows wrap; Home/End and Ctrl+Home/End move to row/board ends; Page Up/Down move three rows with clamping. Ctrl supports multiple-cell selection; Ctrl+A selects all. Backspace/Delete/Clear restore all candidates; holding Shift or Ctrl empties them. Escape clears the selection and blurs. | [Sudoku.test.tsx](../src/Elems/MainElems/Sudoku.test.tsx) checks navigation and editing; Shift/Ctrl navigation has a `test.todo`. [keyboardListener.test.ts](../src/keyboardListener.test.ts) checks held modifiers and window blur/context-menu cancellation. |
| Candidates and serialization | [PureSudoku.ts](../src/Api/Spaces/PureSudoku.ts): `to81()` represents a solved cell with `1`–`9`, a cell with no candidates with `0`, and other cells with `.`; it appends a newline to each row, including the last. `to729()` records each candidate. | [PureSudoku.test.ts](../src/Api/Spaces/PureSudoku.test.ts) tests imports, candidate edits, clearing, and `to81()`/`to729()` round trips. |
| Solver progression | [Solver.ts](../src/Api/Solver.ts), [Strategies.ts](../src/Api/Strategies/Strategies.ts) | [Solver.test.tsx](../src/Api/Solver.test.tsx) exercises stepping through strategies, invalid boards, and skipping disabled strategies. |
| Strategy controls | [Solver.ts](../src/Api/Solver.ts): Step runs a strategy; Go repeats Step until the strategy index returns to zero. [StrategyItem.tsx](../src/Elems/AsideElems/StrategyItem.tsx) writes toggle state to `solver.disabled`. | [Aside.test.tsx](../src/Elems/Aside.test.tsx) checks switch roles and toggling the disabled appearance; [Solver.test.tsx](../src/Api/Solver.test.tsx) checks skipping a disabled strategy. |
| Undo | [Solver.ts](../src/Api/Solver.ts) calls each [Cell.tsx](../src/Elems/MainElems/Cell.tsx) `undo()`: restore `previousCandidates` when present, then clear explanation state. This uses a per-cell snapshot, rather than a stack of manual edits. | — |
| Import and export formats | [PureSudoku.ts](../src/Api/Spaces/PureSudoku.ts) accepts 81-character, 729-character, and whitespace-separated candidate grids. In `import81()`, non-digits (including `0`) restore all candidates. [Solver.ts](../src/Api/Solver.ts) prompts for import and queues both exports as monospace alerts. | [PureSudoku.test.ts](../src/Api/Spaces/PureSudoku.test.ts) checks board fixtures, a SudokuWiki URL, candidate-grid separators (space, tab, LF, CRLF), and serialization round trips. |
| Explanations and annotations | [StrategyDetails.tsx](../src/Elems/AsideElems/StrategyDetails.tsx) displays the latest step message. [Cell.tsx](../src/Elems/MainElems/Cell.tsx) tracks previous candidates and highlight classes; [CandidatesDiff.tsx](../src/Elems/MainElems/CandidatesDiff.tsx) gives added/eliminated classes precedence over strategy classes. [Candidate.css](../src/Elems/MainElems/Candidate.css) colors additions green and eliminations yellow. | [Strategies.test.tsx](../src/Api/Strategies/Strategies.test.tsx) checks strategy outcomes and candidate changes. |
| Validation and error dialogs | [checkValidity.ts](../src/Api/Strategies/checkValidity.ts) reports empty cells, duplicate solved digits, and missing possibilities in rows/columns/boxes. [checkForSolved.ts](../src/Api/Strategies/checkForSolved.ts) sends validation errors to the [App.tsx](../src/App.tsx) notice queue, rendered by [NoticeWindow.tsx](../src/Elems/NoticeElems/NoticeWindow.tsx). | [checkValidity.test.ts](../src/Api/Strategies/checkValidity.test.ts) checks those invalid-board categories; [App.test.tsx](../src/App.test.tsx) checks alert dismissal, error styling, and prompt cancel/submit/default values. |
| Controls and prompts | [StrategyControls.tsx](../src/Elems/AsideElems/StrategyControls.tsx), [App.tsx](../src/App.tsx): controls include Clear, Import, Export, Go, Step, and Undo. | [App.test.tsx](../src/App.test.tsx) tests alerts and prompts; strategy control testing is marked `test.todo`. |
| Styling | [Sudoku.css](../src/Elems/MainElems/Sudoku.css), [App.css](../src/App.css), [Aside.css](../src/Elems/Aside.css) define the current board and page presentation. | — |
| Print, RTL, and layout | [index.css](../src/index.css) changes palette variables for print. [Sudoku.css](../src/Elems/MainElems/Sudoku.css) moves box-boundary borders for RTL. [App.css](../src/App.css) defines one/two-column layouts at 900px; [Main.css](../src/Elems/Main.css) calculates board dimensions. | — |
| Build and deployment | [package.json](../package.json) defines CRA build/test commands and the `/solver` homepage. [build.yml](../.github/workflows/build.yml) builds and tests on Linux/macOS/Windows and deploys `build/` to GitHub Pages when its ref condition matches `main`. | — |
